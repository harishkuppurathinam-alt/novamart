natural-language Telegram messages.

The architecture must be:

Telegram
    ↓
AI Agent

Tools
    ↓
Business Services

the appropriate tools.

Do NOT implement one command per business operation.
Telegram handlers should mainly pass messages to the agent and return results.

--------------------------------------------------
Billing service
--------------------------------------------------

Functions:

createDraftBill(...)
getDraftBill(...)
addBillItem(...)
removeBillItem(...)
updateBillItemQuantity(...)
calculateBill(...)
finalizeBill(...)

Important:

A bill starts as DRAFT.

Adding/removing/updating items must NOT reduce stock.

Only finalizeBill() reduces stock.

finalizeBill() MUST execute atomically inside a Prisma transaction.

During finalization:

1. Verify bill is still DRAFT.
2. Fetch all current products.
3. Verify sufficient stock for every item.
4. Calculate totals deterministically.
5. Calculate GST in application code.
6. Decrease stock.
7. Snapshot product name and selling price.
8. Mark bill FINALIZED.
9. Store payment method.
10. Set finalizedAt.

If any product has insufficient stock:
- reject the whole transaction
- do not partially update stock
- return a useful error to the agent.

Never let stock become negative.

Repeated finalization of an already FINALIZED bill must not create another
sale or deduct stock again.

--------------------------------------------------
GST
--------------------------------------------------

GST calculations must NOT be performed by the LLM.

Calculate them in deterministic TypeScript code.

For each line:

lineSubtotal = quantity × unitPrice

GST is split equally:

CGST = GST / 2
SGST = GST / 2

Use proper monetary rounding.

Bill totals must be calculated from line items.

==================================================
6. MULTI-TURN BILLING
==================================================

This is a critical requirement.

The following sequence MUST work:

User:
"Make a bill for 2 sugar and 4 Maggi"

Agent creates a DRAFT.

User:
"Remove sugar"

Agent modifies the existing draft.

User:
"Make Maggi 6"

Agent updates the same draft.

User:
"Finalize with UPI"

Agent finalizes the same bill.

Stock is deducted ONLY at this point.

The active draft bill must be persisted in the database, not only kept in
LLM memory.

If the process restarts, the draft should still exist.

9. IDEMPOTENCY
==================================================

Design the bot so duplicate Telegram updates do not create duplicate
business operations.

Track processed Telegram update IDs or use an equivalent reliable mechanism.

Finalizing an already finalized bill must be safe.

Never deduct stock twice.
